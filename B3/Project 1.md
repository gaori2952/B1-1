# Project 1.  Make&Zapier 활용 이메일 자동화 

## 1. 사용한 도구

이번 프로젝트에서는 동일한 이메일 자동화 워크플로우를 구현하기 위해 **Make**와 **Zapier**를 사용하였다.

이메일 수신에는 Gmail, 이메일 요약과 중요도 분류에는 OpenAI 또는 ChatGPT, 결과 저장에는 Notion, 중요 이메일 알림에는 Discord를 사용하였다.

---

## 2. 구현 과정 요약

Gmail에서 새로운 이메일을 확인하면 AI가 이메일의 제목과 본문을 분석하여 내용을 요약하고 중요도를 분류하도록 구성하였다.

중요도는 `높음`, `보통`, `낮음`으로 구분하였다. 모든 이메일은 Notion 데이터베이스에 기록하고, 중요도가 높은 이메일은 Discord에도 알림을 전송하도록 설정하였다.

전체 자동화 과정은 다음과 같다.

```text
Gmail에서 새로운 이메일 확인
        ↓
AI를 이용한 이메일 요약 및 중요도 분류
        ↓
Notion 기록
        ↓
조건 분기
├─ 중요도 높음 → Discord 알림
└─ 중요도 보통·낮음 → X
```

Notion에는 다음 정보를 기록하였다.

- 메일 제목
- 이메일 요약
- 수신일
- 중요도

### 트리거 작동 방식

Make와 Zapier의 Gmail 트리거는 모두 **폴링 방식**으로 작동한다.

폴링 방식은 이메일이 수신되는 순간 바로 실행되는 방식이 아니라, 자동화 도구가 일정한 주기로 Gmail을 확인한 뒤 새로운 이메일이 발견되면 워크플로우를 실행하는 방식이다.

이번 프로젝트에서 Make는 Gmail을 약 15분 간격으로 확인하고, Zapier는 약 2분 간격으로 확인하였다.

---

## 3. 각 도구별 워크플로우

### 3.1 Make 워크플로우

Make에서는 Gmail의 `Watch Emails` 모듈을 트리거로 사용하였다.

```text
Gmail - Watch Emails
        ↓
OpenAI
        ↓
JSON Parse
        ↓
Notion 기록
        ↓
조건 분기(FILTER)
├─ 중요도 높음 → Discord 알림
└─ 중요도 보통·낮음 → X
```

`Watch Emails` 모듈이 설정된 주기마다 Gmail을 확인하고, 새로운 이메일이 발견되면 이메일 정보를 OpenAI 모듈로 전달한다.

OpenAI는 이메일 내용을 요약하고 중요도를 분류한다. 응답은 JSON 형식으로 출력하였으며, JSON Parse 모듈을 이용하여 요약과 중요도 값을 분리하였다.

이후 Router와 Filter를 사용하여 중요도가 높은 이메일과 그 외 이메일의 경로를 나누었다. 중요도가 높은 이메일은 Notion에 기록한 뒤 Discord 알림을 전송하고, 중요도가 보통 또는 낮은 이메일은 Notion에만 기록하였다.

### 3.2 Zapier 워크플로우

Zapier에서는 Gmail의 `New Email`을 트리거로 사용하였다.

```text
Gmail - New Email
        ↓
ChatGPT
        ↓
Notion 기록
        ↓
조건 분기(FIRTER)
├─ 중요도 높음 → Discord 알림
└─ 중요도 보통·낮음 → X
```

Gmail 트리거가 설정된 주기마다 새로운 이메일을 확인하고, 이메일이 발견되면 ChatGPT 단계로 전달한다.

ChatGPT는 이메일 내용을 요약하고 중요도를 분류한다. 이후 조건 분기를 통해 중요도가 높은 이메일은 Notion에 기록한 뒤 Discord 알림을 전송하고, 중요도가 보통 또는 낮은 이메일은 Notion에만 기록하였다.

Zapier에서는 Copilot에 만들고 싶은 자동화 내용을 입력하여 기본적인 워크플로우를 생성한 뒤, 각 단계의 입력값과 연결 정보를 직접 수정하였다.

## 4. 실행 결과

### 4.1 Make 실행 결과

Make 시나리오를 활성화한 뒤 Gmail로 테스트 이메일을 전송하였다.

Make가 설정된 주기에 따라 새로운 이메일을 확인한 후 이메일 제목과 본문을 OpenAI로 전달하였다. OpenAI가 생성한 요약과 중요도가 JSON Parse를 통해 분리되었으며, Router의 조건에 따라 알맞은 경로가 실행되었다.

모든 이메일이 Notion에 정상적으로 기록되었고, 중요도가 높은 이메일은 Discord에도 알림이 전송되는 것을 확인하였다.

## 5. 비교 분석 (차이점 및 장단점,적합한 상황)

| 비교 항목 | Make | Zapier |
|---|---|---|
| UI·UX 구성 방식 | 시각적 캔버스와 드래그 앤 드롭 방식의 노드 구조를 사용한다. 앱 아이콘과 연결선을 통해 전체 자동화 흐름을 한눈에 확인하기 쉽고, 노드를 자유롭게 배치할 수 있다. | Trigger와 Action이 위에서 아래로 이어지는 수직 하향식 구조를 사용한다. 단계별 설정 방식이므로 선형적인 자동화 흐름을 파악하기 쉽다. |
| AI 지원 여부 | Maia라는 AI 지원 기능이 있지만 이번 프로젝트에서 사용한 계정에서는 이용할 수 없어 워크플로우를 직접 구성하였다. | Copilot을 이용해 자연어로 원하는 자동화를 입력하고 기본 워크플로우를 생성할 수 있다. 이번 프로젝트에서도 Copilot을 사용하였다. |
| 설정 및 학습 난이도 | 초기 진입 장벽이 비교적 높다. 모듈 연결, 데이터 매핑, 자체 함수와 문법, JSON Parse, Router와 Filter 설정에 대한 이해가 필요하다. | 친숙한 UI와 단계별 가이드가 제공되어 설정 과정이 비교적 쉽다. 노코드 자동화를 처음 사용하는 사용자에게 적합하다. |
| 트리거 방식 | Gmail의 `Watch Emails` 모듈을 사용하는 폴링 방식이다. 일정한 주기로 Gmail을 확인한 뒤 새로운 이메일을 처리한다. | Gmail의 `New Email` Trigger를 사용하는 폴링 방식이다. 일정한 주기로 Gmail을 확인한 뒤 새로운 이메일을 처리한다. |
| 트리거 확인 빈도 | 약 15분 간격으로 Gmail을 확인하였다. | 약 2분 간격으로 Gmail을 확인하였다. |
| 연동 서비스 및 커넥터 범위 | 약 3,000개 이상의 앱을 지원한다. 세부 API Action과 Raw HTTP 요청, Webhook 등을 이용한 데이터 가공 능력이 있다. | 약 9,000개 이상의 앱을 지원하여 더 큰 앱 연동 생태계를 제공한다. 다양한 서비스와 빠르게 연결하기에 유리하다. |
| 조건 분기 | Router와 Filter를 이용해 여러 실행 경로를 시각적으로 구성할 수 있다. 무료 플랜에서도 다단계 구성과 조건 분기를 활용할 수 있어 복잡한 자동화에 적합하다. | 조건 분기와 다단계 자동화를 구성할 수 있지만 무료 플랜에서는 제한된다. 분기가 많아지면 하향식 계층 구조가 길어질 수 있다. |
| 무료 플랜 제공 범위 | 월 1,000 Credits를 제공하며 최대 2개의 활성 시나리오를 사용할 수 있다. 월 데이터 전송량은 100MB로 제한된다. 무료 플랜에서도 다단계 자동화와 조건 분기를 활용할 수 있다. | 월 100 Tasks를 제공하며 월 데이터 전송량 제한은 없다. 무료 플랜에서는 기본적인 단일 단계 자동화만 사용할 수 있고, 분기와 다단계 기능은 제한된다. |
| 실행 로그 및 디버깅 | 각 노드의 입력값과 출력값을 그래픽 버블 형태로 확인할 수 있다. 데이터가 어느 단계에서 어떻게 처리되었는지 직관적으로 추적하기 쉽다. | Task History에서 각 단계의 실행 성공 및 실패 여부와 처리 데이터를 텍스트 또는 JSON 형태로 순서대로 확인할 수 있다. |
| 장점 | 자동화 전체 구조를 시각적으로 확인하기 쉽고, 복잡한 조건 분기와 데이터 가공에 유리하다. 무료 플랜에서도 비교적 다양한 기능을 사용할 수 있다. | 설정 과정이 간단하고 Copilot을 활용해 빠르게 자동화를 구성할 수 있다. 지원하는 연동 서비스의 수가 많다. |
| 단점 | 처음 사용할 때 데이터 매핑, 함수, Router, Filter 등의 기능을 익혀야 하므로 설정 난이도가 높다. | 무료 플랜에서 다단계 자동화와 조건 분기 사용이 제한되며, 복잡한 구조에서는 전체 흐름을 한눈에 보기 어렵다. |
| 적합한 상황 | 여러 단계의 데이터 처리, API 연동, 복잡한 조건 분기가 필요한 자동화에 적합하다. | 다양한 앱을 간단하게 연결하거나 초보자가 빠르게 자동화를 구현하는 상황에 적합하다. |
